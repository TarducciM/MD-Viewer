# MD Viewer — project notes

Desktop Markdown viewer/editor. Tauri 2 (Rust + WebView2) shell, vanilla TypeScript + Vite frontend, no UI framework. See [README.md](README.md) for the user-facing feature list in Italian/English.

## Commands

```bash
npm install
npm run tauri dev      # dev app with hot reload
npm run typecheck      # tsc --noEmit
npm test               # vitest run
npm run build           # tsc + vite build (frontend only, sanity check)
npm run tauri build     # full native build (installer/bundle)
```

CI (`.github/workflows/ci.yml`) runs typecheck + test + build on every push/PR to `main`, plus `cargo test` for the Rust side on Linux.

## Release process

Releases are **not** automatic on push. To cut one:

1. Bump the version in three places (must match): `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`.
2. Run `cargo check` in `src-tauri/` once to sync `Cargo.lock`'s own version entry.
3. `npm run typecheck && npm test && npm run build` before committing.
4. Commit, then `git tag vX.Y.Z && git push origin main && git push origin vX.Y.Z`.
5. `.github/workflows/release.yml` first re-verifies (`typecheck` + `test` + `build` + `cargo test`, mirroring CI) in a `verify` job, then builds Windows, macOS (arm64 + x64), and Linux (deb/rpm/AppImage), and creates a draft GitHub Release with all assets plus an auto-generated changelog and a downloads table.
6. If verification or any platform build fails, a `cleanup-on-failure` job deletes the partial draft automatically (the tag is left untouched — just re-run the failed job after fixing the issue).
7. **The release auto-publishes.** Once verify + every platform build + notes generation succeed, the `notes` job's last step runs `gh release edit vX.Y.Z --draft=false` itself — no manual approval step, no need to ask the user first. This is a deliberate standing instruction from the project owner (given 2026-08-27), reversing the earlier draft-only-until-asked policy. If a build fails partway, the draft is deleted by `cleanup-on-failure` as before, so nothing half-built ever goes public — the safety gate is "did every job succeed," not "did a human review it."

## Source layout (`src/`)

- `main.ts` — app state and wiring. One sidebar file tree tied to a single `currentRoot`; any number of independently-open file tabs (`Tab[]`) each with their own text/encoding/line-ending/dirty/edit state, switchable without losing unsaved edits. Only the *active* tab ever has a live `MarkdownEditorHandle`; switching tabs captures the outgoing tab's live buffer into `editBuffer` and destroys the CodeMirror instance, recreating it on return. Opening a folder never closes existing tabs; it only replaces the sidebar tree. The in-app File/View/Help menu bar (`#menubar`) is a second, separate row above the icon toolbar — both stay in sync since they call the same functions.
- `markdown.ts` — markdown-it setup, Darcula/light-aware syntax highlighting, code block line numbering, relative image path resolution via `convertFileSrc`.
- `editor.ts` — CodeMirror 6 setup for edit mode: markdown language support, word-completion source (document words + `wordlists.ts`), and the formatting-toolbar actions (bold/italic/link/table/etc.).
- `fileTree.ts` / `treeView.ts` — recursive directory scan (data) and sidebar rendering (DOM), kept separate on purpose.
- `settings.ts` / `settingsPanel.ts` — persisted settings (localStorage) and the settings dialog.
- `i18n.ts` — IT/EN dictionaries; UI strings use `data-i18n`/`data-i18n-title` attributes, applied via `applyTranslations()`.
- `encoding.ts` — text encoding (UTF-8/UTF-8 BOM/UTF-16 LE/BE) and line-ending (LF/CRLF) detection + conversion. Files are read/written as raw bytes (`readFile`/`writeFile`), not `readTextFile`, specifically so encoding can be detected.
- `export.ts` — plain-text export (tables become ASCII-art grids) and standalone-HTML export.
- `docxExport.ts` — walks markdown-it's token stream directly (not the rendered HTML) to build a real `.docx` via the `docx` library — real paragraphs/tables/lists, not pasted HTML.

## Conventions

- **No AI-authorship traces anywhere in this repo.** No `Co-Authored-By` trailers, no "generated by AI" mentions in code/comments/commits/docs. Commit messages should read as normal human-written messages. This is a standing, explicit preference for this project — grep for "claude"/"anthropic" (case-insensitive) before committing if in doubt.
- **No third-party brand names** in UI copy or code (no "JetBrains", "IntelliJ", "Darcula", etc.) — the dark/light themes are described generically ("Scuro"/"Chiaro", "IDE-inspired"). This was a deliberate scrub done once; don't reintroduce them.
- Tests live next to the module they cover (`foo.ts` → `foo.test.ts`), Vitest + happy-dom. Favor testing pure logic (encoding round-trips, markdown rendering edge cases, tree filtering) over UI wiring.
- Capabilities/permissions are broad on purpose (`"path": "**"` scope for fs, dialog) since this is a local desktop tool the user points at arbitrary files/folders — not a sandboxed or networked app.
